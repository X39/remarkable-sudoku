# remarkable-sudoku

Sudoku for the reMarkable Paper Pro. You write the digits into the cells with the pen and the app reads
your handwriting. It runs as an [AppLoad](https://github.com/asivery/rm-appload) app (QML inside xochitl).

Developed and tested on a **Paper Pro, firmware 3.29.1**. Other devices and firmware versions are untested.

## Features

- Handwriting on the board: no cell selection, no number pad. A small CNN (about 109k weights, runs in the
  app's JavaScript, no network) reads each digit 1-9 and shows how sure it is.
- Low-confidence reads (under 80%) are decided by the Sudoku rules: among the plausible digits, the best one
  that does not clash with its row, column or box wins.
- The eraser end of the pen erases ink (detected by a small Rust helper that watches the pen digitizer).
- Ghost mode for 3x3 pencil-mark digits via taps, undo/redo, Check, optional live error marking.
- New game panel with difficulty presets and a clue stepper.
- E-ink friendly: the round button top-left does a full-panel clean refresh. The board also clears itself
  after you leave the New game panel and 30 s after the last change (option "Clean refresh").
- The game is saved when you leave with the x button (top-right) and restored next time.

## Install

You need a Paper Pro with [xovi](https://github.com/asivery/rm-xovi-extensions) and
[AppLoad](https://github.com/asivery/rm-appload) installed (the easiest way is [Vellum](https://github.com/vellum-dev/vellum)).

**With Vellum** (once the package is accepted into the Vellum repository, see [docs/VELLUM.md](docs/VELLUM.md)):

```sh
vellum add sudoku
```

**Manually:** download `sudoku-appload-<version>-aarch64.zip` from the
[releases](https://github.com/X39/remarkable-sudoku/releases) and unpack it so that this layout exists on the tablet:

```
/home/root/xovi/exthome/appload/sudoku/manifest.json
/home/root/xovi/exthome/appload/sudoku/icon.png
/home/root/xovi/exthome/appload/sudoku/resources.rcc
/home/root/xovi/exthome/appload/sudoku/backend/entry     (must be executable)
```

Then reload AppLoad (or restart xochitl) and open **Sudoku** from the AppLoad launcher. A new build is only
picked up after such a reload.

## Build

Requirements: Rust with the `aarch64-unknown-linux-musl` target (linking uses `rust-lld`, no cross compiler
needed) and Qt's `rcc` (`pip install PySide6` provides one, or `qt6-base-dev-tools`).

```sh
rustup target add aarch64-unknown-linux-musl
bash tools/build.sh      # -> dist/sudoku/   (RCC=/path/to/rcc to choose rcc, SKIP_BACKEND=1 for UI only)
bash tools/package.sh    # -> dist/release/  (tar.gz, zip, SHA512SUMS)
bash tools/deploy.sh     # copy dist/sudoku to the tablet over USB SSH (RM_HOST, RM_KEY)
```

The build writes `ui/build-stamp.txt`; the app logs it at startup (`journalctl | grep "DBG build"` on the
tablet) so you can tell which build is running.

Releases: bump `VERSION`, tag `vX.Y.Z` and push the tag. `.github/workflows/release.yml` builds and publishes
the archives. CI (`.github/workflows/ci.yml`) builds on every push and checks the recognizer and the VELBUILD.

## Digit model

`ui/digit-model.js` is generated by `tools/train_cnn.py` from MNIST plus synthetic pen strokes for the digits
that MNIST-trained models confuse with handwritten pen styles (flagged 1 vs 7, rounded-foot 4 vs 9).

```sh
pip install -r requirements.txt
python tools/train_cnn.py epochs=18 write      # SYN=5000 is the default synthetic samples per class
```

Delete `build/data/synthetic_5000.npz` after changing a generator (the cache is keyed only by `SYN`).
`tools/user-samples/*.json` are recorded real handwriting (label = true digit). They are a **test set only**:
`node tools/eval-samples.js` scores the shipped model on them and `node tools/replay-ink.js <save.json>`
replays a saved game. Do not train on them until there are hundreds of samples and a held-out split shows a gain.
